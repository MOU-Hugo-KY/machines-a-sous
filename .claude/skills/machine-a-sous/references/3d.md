# Machines en 3D

Exemples complets : `jeux/constella-3d.html` et `jeux/champi-pop-3d.html`. Leurs modèles sont dans `kit/exemple-constella.js` et `kit/exemple-champi.js`, et leurs décors dans `kit/decor-constella.js` et `kit/decor-champi.js`.

**Le plus rapide pour passer une machine 2D en 3D** : écris ses modèles et son décor, puis lance :

```bash
python3 .claude/skills/machine-a-sous/scripts/passer-en-3d.py jeux/<nom>.html <modeles.js> <decor.js> jeux/<nom>-3d.html "<Nom> 3D"
```

Le script colle le kit, les modèles et le décor, ajoute le CSS et branche le chargement de la 3D. Il repart toujours de la version 2D : relance-le après chaque retouche des modèles ou du décor.

## Le principe

Afficher 36 scènes WebGL en même temps serait lourd, surtout sur téléphone. On fait donc comme les jeux mobiles : **on modélise chaque symbole en 3D avec Three.js, puis on le « cuit » au chargement en deux planches d'images** (24 images en boucle) :

- **repos** : respiration, léger balancement, clignement des yeux ;
- **victoire** : accroupi, saut joyeux avec un petit dandinement, réception écrasée. Le personnage reste de face (un tour complet montrait son dos, et faisait trop de mouvement quand beaucoup de cases gagnent).

Chaque case affiche sa planche en fond CSS qui défile (`background-position` avec `steps(n, jump-none)`) : c'est aussi fluide qu'une vidéo, et aussi léger qu'une image. N'anime jamais les planches avec `transform` sur une grande image : chaque case devient alors un calque graphique, et au-delà d'une trentaine de cases la carte graphique sature (cases vides ou qui clignotent, surtout sous Windows). Quand une case gagne (`.cell.win` ou `.cell.scatwin`), le CSS passe sur la planche de victoire. Il n'y a **pas de personnages 3D qui tournent autour des grands écrans** (entrée du bonus, gros gains) : on l'a essayé, c'était trop chargé. Ces écrans restent en 2D, avec leurs médailles et leur texte, et le décor se met en pause derrière eux.

La machine démarre **tout de suite avec ses dessins 2D**. Les planches se cuisent en arrière-plan (moins d'une seconde avec une carte graphique, une dizaine de secondes en rendu logiciel), puis la grille bascule en 3D. Si Three.js ne se charge pas (hors ligne, CDN bloqué), la machine reste en 2D et fonctionne normalement. Une machine 3D garde donc un `ART` en SVG : il peut être plus simple que dans une machine 2D, mais il doit exister.

## Le kit (`kit/kit3d.js`, à coller tel quel dans la machine)

- `KIT3D(THREE)` renvoie les briques :
  - `part(géométrie, couleur, { pos, rot, scale, ink, opacity, emissive, glow })` : une pièce en **matériau toon** (ombrage cel à 4 paliers), avec un **contour d'encre** par coque inversée. `ink` règle l'épaisseur (0,05 par défaut, 0 pour aucun contour).
  - `G.sphere / box (arrondie) / cyl / cone / torus (arc possible) / capsule / lathe (profil tourné) / extrude (forme 2D) / star / lumpy (sphère bosselée)`.
  - `face(R, 'smile' | 'happy' | 'sleep' | 'o', { y, spread, size, blush, z })` : les yeux (avec leur reflet), les joues roses et la bouche, posés sur une tête de rayon R. Avec `z`, sur une face plate. Le groupe des yeux s'appelle `eyes`, ce qui permet le clignement.
  - `mat(couleur, opts)`, `studio()`, `ANIM.idle/win`, `ease`, `bake(modèle)`, `html(planches)`, `live(canvas)`.
  - Pour le décor : `sky(haut, horizon, bas)` (ciel en dégradé, couleurs modifiables à chaque image), `dots(n, pos, couleur, opts)` (étoiles, lucioles, braises), `lerpColor`.
  - `K.pbr(couleur, { metal, rough, emissive, glow })` : matériau réaliste (métal, plastique brillant) pour le style premium (`references/styles.md`), à combiner avec `ink: 0`.
  - `K.INK.color` change la couleur des contours (brun pour Champi Pop). Règle-la au début de `ART3D_MODELS`.
- `CHARGE3D(ART, ART3D_MODELS, DECOR3D)` : charge Three.js depuis jsDelivr, lance le décor 3D (facultatif), cuit tous les modèles, remplace `ART.SYMS`, `ART.SCAT` et les `VARIANTES`, prépare la scène en direct, puis envoie l'événement `art3d`. Il renseigne `window.ART3D_STATE` (`chargement`, `ok` ou `erreur`), que `check.js` lit.
- `STAGE3D` : ses fonctions restent vides exprès (la ronde 3D a été retirée : trop chargée). N'y ajoute pas d'animation autour des grands écrans.

## Écrire les modèles : `ART3D_MODELS(K)`

```js
const ART3D_MODELS = K => {
  const { THREE, part, G, face, mat, TAU } = K;
  const grp = (...c) => { const g = new THREE.Group(); g.add(...c); return g; };
  function crabe() {
    const corps = part(G.sphere(0.8), 0xFF7A59, { scale: [1.2, 0.8, 0.9] });
    const pinces = [-1, 1].map(s => part(G.sphere(0.3), 0xFF5A3A, { pos: [s * 1.05, 0.2, 0.2], scale: [1, 0.7, 0.6] }));
    const g = grp(corps, ...pinces, face(0.8, 'happy', { y: 0.05 }));
    g.userData.anim = { idle(t) { pinces.forEach((p, i) => p.rotation.z = Math.sin(t * TAU * 2 + i) * 0.3); } }; // en plus de l'animation commune
    return g;
  }
  return { SYMS: [/* 8 fonctions, même ordre que ENGINE.SYMS */], SCAT: …, VARIANTES: { /* ex. star: { gold: () => … } */ } };
};
```

Les règles pour un rendu propre :

- **Taille** : le modèle tient dans un rayon d'environ 1,2 autour de l'origine (la caméra cadre ±1,8). Le saut de victoire monte de 0,42 : laisse de la marge en haut.
- **Formes simples et rondes** : sphères écrasées, capsules, profils tournés, extrusions arrondies. Des proportions de jouet (tête grosse, petits membres). Pas plus d'une vingtaine de pièces par symbole.
- **Couleurs** : reprends la palette du thème. Une couleur principale par symbole, plus foncée pour les détails. `emissive` pour ce qui brille (flamme, lentille, étoile).
- **Transparent = sans contour** (`ink: 0`), sinon la coque sombre se voit au travers (bulle, verre, queue de comète). Ajoute plutôt un reflet blanc (un arc de `torus`).
- **Personnalité** : chaque symbole a son visage (`face`) et au moins une animation propre dans `userData.anim` : une flamme qui vacille, des rayons qui tournent, des ailes qui battent, une queue qui remue… Garde la boucle **cyclique** (fonctions de `t * TAU`, avec des fréquences entières).
- Les 4 gros symboles sont plus détaillés que les 4 petits. Le scatter se reconnaît au premier coup d'œil, même en tout petit.

## Le décor 3D autour de la machine

C'est ce qui rend la machine vraiment spectaculaire. Une scène 3D plein écran remplace le paysage 2D derrière la machine : un seul rendu WebGL, en direct, qui réagit au bonus. `CHARGE3D(ART, ART3D_MODELS, DECOR3D)` la lance **avant** la cuisson des symboles, pour que le décor apparaisse tout de suite.

```js
const DECOR3D = (K, M) => ({   // M : les modèles de la machine, pour en poser des géants dans le décor
  build(scene, cam) {
    // ciel (K.sky), lumières, brouillard, sol, objets, habitants, particules (K.dots)…
    return {
      camFor(aspect) { /* recadrage : plus de recul sur téléphone, groupe de premier plan visible ou non */ return { pos, target }; },
      update(t, dt, s) { /* s.bonus va de 0 à 1 en douceur quand le bonus commence : jour → nuit, aurores… */ },
    };
  },
});
```

La recette des deux exemples :

- **Composition** : la machine cache le centre de l'écran. Mets l'intérêt **sur les côtés** (ordinateur) et **en haut et en bas** (téléphone) : le ciel et ses astres en haut, un premier plan riche à gauche et à droite (champignons géants, tente et feu de camp, rocher et chat), des habitants animés au sol. `camFor` recule la caméra quand l'écran est étroit et affiche un petit groupe de premier plan centré, visible sous la machine quand on fait défiler la page.
- **Profondeur** : 4 plans au minimum. Le ciel en dégradé avec étoiles ou soleil, les montagnes ou collines dans le brouillard, la rangée d'arbres et les bâtiments, puis le premier plan. Le brouillard (`scene.fog`), de la couleur de l'horizon, lie le tout.
- **Vie** : au moins 8 choses bougent en continu, avec des rythmes différents. Par exemple : feuilles qui tombent (InstancedMesh recyclé), fumée de cheminée, canard sur l'étang, biche qui broute, renard qui remue la queue, lucioles, ailes de moulin, étoiles filantes, aurores en shader, fusée qui passe.
- **Bonus** : `s.bonus` fait basculer l'ambiance. Interpole les couleurs du ciel, du brouillard, des lumières et du sol, allume les fenêtres, les lanternes et les halos, fait monter les aurores et fait apparaître les lucioles et les étoiles.
- **Réutilise les personnages de la machine** en géant (lune, planète, champignons) : c'est ce qui donne l'impression d'un univers cohérent. Clone leurs matériaux avant de les modifier (lueur la nuit, pas de brouillard pour les astres), mais jamais ceux des contours (`side === BackSide`).
- **Légèreté** : géométries partagées, `G.lumpy(r, amp, graine, 3)` (détail 3) pour les feuillages, InstancedMesh pour tout ce qui se répète en grand nombre, halos en sprites additifs, et `K.dots` pour les particules (points doux qui scintillent). Le kit plafonne la résolution à 1,5× et s'arrête quand l'onglet est caché.
- Le kit ajoute une **parallaxe** qui suit la souris ou l'inclinaison du téléphone, et une descente de caméra quand on fait défiler la page.
- Une fois la première image du décor affichée, `<body>` reçoit la classe `decor3d`. Le CSS ajouté par `passer-en-3d.py` masque alors le paysage 2D (`.scene`, `.flock`, et les décors et animaux de `.floor`). Si ta machine a d'autres éléments de décor 2D, masque-les aussi.

## Brancher la 3D dans une machine (à la main)

1. Colle le contenu de `kit/kit3d.js` puis ton `ART3D_MODELS` juste avant l'IIFE de l'interface (`(() => { const E = ENGINE; …`).
2. Ajoute le bloc CSS des symboles 3D (copie-le de `jeux/constella-3d.html`, section « symboles 3D ») : planches, états de case (`pending`, `drop`, `win`…), tailles dans les médailles, la danse, les offres et les règles, `#stage3d`, et l'arrêt des animations avec les mouvements réduits.
3. Dans l'interface :
   - à la fin : `addEventListener('art3d', () => { if (!S.busy && !document.body.classList.contains('bonus')) showStatic(E.spinBase()); }); CHARGE3D(ART, ART3D_MODELS, DECOR3D);`
4. Si un élément du bonus est dessiné par une fonction d'`ART` (étoile, champignon, pouvoir…), déclare-le dans `VARIANTES` pour qu'il passe aussi en 3D.

## Mettre au point les modèles

`check.js` attend la fin de la cuisson et échoue si la 3D est en erreur. Pour itérer vite sur les modèles, regarde `jeux/captures/<nom>/telephone-accueil.png` (grille en 3D). Pour voir la ronde, lance la page sans mouvements réduits et appelle `STAGE3D.big(4)` depuis la console. Dans ce conteneur, jsDelivr est bloqué : `check.js` sert alors Three.js depuis `scripts/node_modules` (`npm i --prefix .claude/skills/machine-a-sous/scripts`). Dans l'artifact publié, le CDN fonctionne.
